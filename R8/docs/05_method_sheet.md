# 手法シート（報告用・6系統）

報告ではスイープ候補を全部並べず、**系統ごとに QR 検出が最も良い結果を代表**として出す。  
このシートは「何を・何フレームで・どう切ったか」を揃えて書くためのもの。

対象プロファイル: **mid_fast**（いまの主データ）。  
共通入力: 120フレーム → max-channel 隣接差分系列 \(d(t)\)（長さ ≈119）。

採用ルール（実装）: 条件×手法内で `pixel_acc_all` 最大のスイープを adopted。報告の「最良」は、方針として **デコード成功を優先**し、同点なら accuracy / 単純な設定を選ぶ、でよい（スライドでは一言注記）。

---

## 共通条件（全手法）

| 項目 | 内容 |
|---|---|
| 切り出し | 条件ブロックの 2〜4 秒、連続 **120フレーム** |
| 信号 \(d(t)\) | 隣接フレームの max-channel 差分（符号付き）。全手法の共通前段 |
| QR探索 | mid-search: まず濃淡のまま（`gray`）、だめならメディアン＋Otsu（`median_otsu`） |
| 地図の色 | 変化大／スコア高 → **黒**、それ以外 → 白（または gray では濃淡） |

---

## 1. 隣接フレーム差分（pair）

| 項目 | 内容 |
|---|---|
| ねらい | 点滅の**瞬間の切り替わり**をそのまま見る |
| 使うフレーム | 120枚から得た \(d(t)\) のうち、**先頭10＋末尾10**の隣接ペア（最大20マップ）。mid_fast: `pair_each_end=10` |
| スコア | 各ペア時刻の差分（増減どちらも「変化」） |
| 二値化の対象 | **生の差分値**（正規化しない） |
| 閾値の決め方 | 固定候補をスイープ: **`th ∈ {4, 8, 12}`**（内部では `th/255` と比較）。条件ごとに accuracy 最大を採用 |
| 出力 pass | `pair` のみ（gray/num なし） |
| 一言 | 最も単純。背景テクスチャに弱いことがある |

---

## 2. 複数フレームでの合計差分（accum）

| 項目 | 内容 |
|---|---|
| ねらい | 短い時間で変化を**積算**し、単発ノイズを抑える |
| 使うフレーム | \(d(t)\) 全長を、長さ **`n=5`** の非重複窓に分割（各窓が1マップ）。例: \(t=0..4\), \(5..9\), … |
| スコア | 窓内で画素ごと \(\sum \|d(t)\|\) |
| 二値化の対象 | **積算スコアそのもの**（正規化しない） |
| 閾値の決め方 | 固定候補: **`th ∈ {8, 16, 24, 32}`**（`th/255` と比較）。加えて **gray（`accum_num`）**: 積算スコアを min–max 正規化し濃淡のまま読取（固定 th なし） |
| 出力 pass | `accum`（binary） / `accum_num`（gray） |
| 報告 | 両 pass を試し、系統代表は読取が良い方（または binary を主・num を補足） |
| 一言 | pair より時間方向にならす |

---

## 3. 時間方向の標準偏差（stat_std）

| 項目 | 内容 |
|---|---|
| ねらい | 「いつ変わったか」ではなく、時間方向に**揺れが大きい画素**を信号とみなす |
| 使うフレーム | \(d(t)\) の**全時間**（約119サンプル）→ 地図は条件あたり原則1枚 |
| スコア | 画素ごとの \(\mathrm{std}_t\, d(t)\) |
| 二値化の対象 | **std マップ**（正規化しない） |
| 閾値の決め方 | 固定候補: **`th ∈ {4, 8, 12}`**（`th/255`）。加えて **`stat_std_num`**: std を正規化グレーで読取 |
| 出力 pass | `stat_std` / `stat_std_num` |
| 一言 | 周波数は見ない。蛍光灯など別周期にも反応しうる |

---

## 4. 時間方向の分散（stat_var）

| 項目 | 内容 |
|---|---|
| ねらい | std と同じ「時間ばらつき」だが、**分散（二乗）**で強い揺れを強調 |
| 使うフレーム | \(d(t)\) 全時間 → 地図1枚 |
| スコア | 画素ごとの \(\mathrm{var}_t\, d(t) = (\mathrm{std})^2\) |
| 二値化の対象 | **var マップ**（正規化しない） |
| 閾値の決め方 | 固定候補: **`th ∈ {1, 2}`**（スケールが小さいので th も小さめ）。**num なし** |
| 出力 pass | `stat_var` のみ |
| 一言 | std と同族。閾値スケールだけ違う別スイープ |

---

## 5. ロックイン（定点滅周波数との相関）

| 項目 | 内容 |
|---|---|
| ねらい | 想定した点滅周波数 \(f\) の正弦／余弦と \(d(t)\) を掛け、**その周波数の振幅が大きい画素**を強調する |
| 使うフレーム | \(d(t)\) 全時間 |
| スコア | 位相 \(\phi\) を変えながら \(A=\sqrt{I^2+Q^2}\) を計算し、位相スイープの最大 \(A\)（mid_fast の位相分割: **`phase_steps=8`**） |
| 目標周波数 | 表示 rate とカメラ fps から自動候補（rate/2・半分・rate/4・3rate/4・50/60Hz の折り畳みなど。2 Hz 未満は除外） |
| 二値化の対象 | **振幅マップを [0,1] 正規化したあと** |
| 閾値の決め方（binary・現行 mid_fast） | 次をスイープし、条件ごとに最良を採用: **固定 0.30 / 0.50 / 0.70**（コード 30/50/70）、**Otsu**、**adaptive**。※旧 4/8/12（実質 th/255）はスケール崩壊のため mid_fast では使わない。既存 CSV に残っていれば比較用 |
| gray | **`lockin_num`**: 同じ振幅マップを濃淡のまま読取（固定 th なし。周波数・位相はスイープ） |
| 出力 pass | `lockin` / `lockin_num` |
| 一言 | 周波数を明示する点で pair/accum/stat と違う |

数式（報告用）:

\[
I=\sum_t d(t)\cos(2\pi f t+\phi),\quad
Q=\sum_t d(t)\sin(2\pi f t+\phi),\quad
A=\sqrt{I^2+Q^2}
\]

---

## 6. 時間 FFT（目標周波数近傍のスペクトル）

| 項目 | 内容 |
|---|---|
| ねらい | 画素ごとの \(d(t)\) を FFT し、**目標周波数近傍のスペクトル強度（対ノイズ比）**をスコアにする |
| 使うフレーム | \(d(t)\) 全時間。前処理: detrend + Hann 窓 |
| スコア | 目標 \(f\) の前後 **`band_radius=2`** ビンの最大振幅 / ノイズ床 |
| 目標周波数 | lockin と同じ hard 系候補 |
| 二値化の対象 | **スコアマップを [0,1] 正規化したあと** |
| 閾値の決め方（binary・現行 mid_fast） | lockin と同じ: **0.30 / 0.50 / 0.70、Otsu、adaptive**。旧 th/255 はほぼ読めず（追記前データで確認済み） |
| gray | **`fourier_num`**: 同じ FFT スコアを濃淡のまま読取。追記前データでは binary 旧 th より大幅に優位 |
| 出力 pass | `fourier` / `fourier_num` |
| 一言 | lockin と同様に周波数選択的。帯域付きスペクトルを見る点が違う |

---

## 報告時のまとめ方（推奨）

1. **6行表**: 系統名 / 使用フレームの要約 / 閾値の要約 / QR成功率（代表）  
2. 各系統の「代表」は、その系統の全スイープ・（あれば）binary/num のうち **読取最良**  
3. スライド本文に候補一覧は出さない。付録または「スイープした軸」だけ1行  
4. fourier は「旧固定 th が無効 → 正規化後の妥当な切る方／gray」を短く注記すると議論が伝わる
